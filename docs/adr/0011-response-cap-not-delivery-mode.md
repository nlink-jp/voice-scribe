# ADR-0011: レスポンス量は `max_bytes` でキャップし、配送方法を切り替えない

- Status: Accepted
- Date: 2026-09-14

## Context

`[mcp] inline_threshold`（既定 8192 バイト）は、転記が閾値以下なら `text` に全文を、
超えたら `text` を捨てて `excerpt` + `path` を返す、という**配送方法の切り替え**だった。
ファイル自体は閾値に関係なく常に書かれていたので、これはスピル機構ではない。しかし
決めている内容は同じ性質のもの — **「この結果は呼び出し側のコンテキストに載るか」を
サーバーが判断している**。

組織としては 2026-09-06 に「大きすぎる結果のファイル化はランタイムの仕事」と決めており、
splunk-mcp（ADR-0004）と pcap-analyzer-mcp（ADR-0009）は同日にスピルを撤去して
「明示キャップ＋落とした分の計上」へ寄せた。両者の要点は、サーバーはモデルの
コンテキスト窓を観測できないので、**閾値は必ずどこかの呼び出し側にとって外れる**という
ことである。8192 バイトという既定は、40 分の会話をプレーンテキストで、あるいは数分を
JSON で持てる程度の量にすぎず、それを超えた瞬間にモデルは本文を一切受け取らなくなる。

一方この判断には前 2 者と違う点がある。**転記ファイルは成果物である。** srt/vtt は
動画プレーヤーに渡す実ファイルだし、json も後段のツールが読む。pcap で言えば
`extract_objects` の抽出オブジェクトに当たり、`work_dir` が要る理由はそのまま残る。
撤回すべきなのはファイルではなく、**レスポンス量がファイルの有無や本文の有無を
左右するという構造**である。

## Decision

1. `inline_threshold` を廃止し、**`max_bytes`**（config `[mcp] max_bytes`、ツール引数
   `max_bytes`、既定 65536、`0` は無制限）に置き換える。65536 は
   pcap-analyzer-mcp の `output.max_bytes` と同じ値で、当 org の他サーバーに出会った
   モデルが同じ数字に出会うようにするため。
2. **結果は常に `text` を運ぶ。** キャップを超えた場合も、超えない範囲までの本文を
   載せる（rune / 行境界で切る。日本語を壊さないため）。`excerpt` フィールドは廃止 —
   「本文の代わりのプレビュー」という概念自体が無くなる。
3. **落とした分を正確に数える。** `truncated: true`、`omitted_bytes`（正確な差分）、
   `note`（言葉での説明）。`bytes` は常に全体の正確なサイズで、`path` /
   `absolute_path` が全文に到達する。
4. **ファイルは常に書く。** キャップはレスポンスだけを縛り、成果物の有無には一切
   関与しない。したがって `work_dir` は必須のまま（ADR-0010）。
5. 旧キーを持つ config は**名指しで拒否**して起動しない。運用者が意図して書いた値を
   「unknown key」で片付けない。

## Consequences

- 破壊的変更。`inline_threshold` を送る呼び出しは strict decode で拒否され、
  config に残っている運用者は起動時に置き換え先を名指しで知らされる。
- 長い転記でモデルが本文をまったく受け取らない状態が無くなる。既定 65536 なら
  8192 の 8 倍が載り、足りなければ `max_bytes: 0` で無制限にできる。
- `excerpt` に依存していた呼び出し側は `text` を読めばよい（短い場合の挙動は同じ）。
- gem-scribe（ADR-0003）も同型に揃える。両者は同じ result 構造を共有している。

## Alternatives considered

| 案 | 不採用の理由 |
|---|---|
| 転記ファイルごと廃止し、splunk / pcap と完全に同じ形にする | 転記は成果物である。srt/vtt は動画に渡す実ファイルで、json も後段が読む。ファイルを消すと `work_dir` が不要になる代わりに、長い転記の全文がジョブの生存期間しか到達できなくなる。pcap も `extract_objects` のためにファイルと `work_dir` を残した |
| `inline_threshold` の既定値だけを上げる | 名前が「閾値を超えたら配送方法が変わる」と言い続ける。モデルが読むのは名前と説明であって実装ではない |
| キャップを設けず常に全文を返す | サーバーが呼び出し側のコンテキストを壊せてしまう。呼び出し側が握るべきつまみを奪う点で、既定を押し付けるのと同じ誤り |
| 文字数（rune 数）でキャップする | `bytes` を既に返しており、フリートの他サーバーもバイトで数える。単位を 1 つにする |
