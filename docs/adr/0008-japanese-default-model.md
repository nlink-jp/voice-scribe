# ADR-0008: 日本語の既定モデルを large-v3-turbo にする

- Status: Proposed
- Date: 2026-08-12

## Context

日本語の既定モデルは初版から `kotoba-whisper-v2.0` で、根拠は
「日本語特化の派生モデルであること」だった。実測して選んだわけではない。

ADR-0007 で後継エンジンを調べた際、副産物として **`large-v3-turbo` のほうが
日本語で良いかもしれない**という結果が出た。`large-v3-turbo` は
**すでにカタログに載っている**（`internal/catalog/catalog.go`）ので、これは
エンジンの乗り換えとは無関係に、今の構成のまま決められる問題である。

kotoba-whisper の model card は whisper-**large-v3** に対しては優位を示している
（ReazonSpeech で CER 11.6 対 14.9）。しかし large-v3-turbo は large-v3 とは
別のモデルであり、その比較は turbo について何も言っていない。

## 実測

M2 Max、2026-08-12。**すべて voice-scribe 本体**（whisper.cpp、q5_0）で測った —
別ランタイムの数字で自分の既定を決めることはできない。ハーネスは
`spike/transcribe-cpp/eval/`。

### 参照ありの精度（CER、各 100 発話、固定 seed、同一 WAV）

| コーパス | 性質 | kotoba-whisper-v2.0 | large-v3-turbo |
|---|---|---:|---:|
| Common Voice 8.0 ja | 読み上げ・多話者クラウド | **9.41%** | 9.57% |
| JSUT basic5000 | 読み上げ・スタジオ | 7.15% | **6.29%** |
| ReazonSpeech test | 放送音声 | 9.08% | **7.82%** |

**ReazonSpeech は kotoba-whisper が学習に使った in-domain セット**である。
そこで負けたことが効いている。CV8 の 0.16 ポイントは n=100 では差と呼べない。

### 実音源での挙動（39 分、BGM 全編、ADR-0006 と同一音源）

参照テキストが無いので CER は測れない。代わりに**構造の健全性**を測った —
ADR-0006 がこの音源で記録した破綻は、まさに構造として現れる種類のものである
（復号が反復ループに落ちる、音声が どのセグメントにも拾われない）。

| 実行 | セグメント | 文字数 | 反復ループ | ループ最大連 | 実時間 |
|---|---:|---:|---:|---:|---:|
| kotoba-whisper-v2.0 | 671 | 8,114 | 1 件 / 4.0 秒 / 出力の 0.1% | 3 | 86 秒 |
| large-v3-turbo | 784 | 11,733 | **4 件 / 81.5 秒 / 出力の 4.1%** | **48** | 173 秒 |
| kotoba-whisper-v2.0 `--vad` | 421 | 5,543 | **0** | 2 | 68 秒 |
| large-v3-turbo `--vad` | 787 | 8,041 | **0** | 2 | 80 秒 |

読み取れることが 3 つある。

**1. turbo は VAD 無しで反復ループに落ちる。** 48 セグメント連続の反復を含む
4 件、合計 81.5 秒。kotoba は 4.0 秒。これは既定構成で出る欠陥である。

**2. VAD を入れると両者ともループが消える。** つまりループは音声でない区間
（この音源では音楽）に対する幻覚であって、音声の誤認識ではない。

**3. ループを消した条件で、turbo は kotoba の 1.45 倍の文字を出す**
（8,041 対 5,543）。倍率は VAD 無しの条件（11,733 対 8,114）と一致するので、
turbo の出力量の多さはループの水増しでは説明できない。

参照が無い以上、**その 1.45 倍が正しいテキストである保証は無い。** ただし
参照のある 3 コーパスすべてで turbo が同等以上であること、そして ADR-0006 が
この音源で「kotoba が一文を丸ごと落とした」ことを記録していることを合わせると、
kotoba がこの音源を取りこぼしている側だと読むのが自然である。

### VAD は既定にできない

`--vad` は文字数を **31% 減らした**（kotoba 8,114 → 5,543、turbo 11,733 → 8,041）。
ループの除去だけでこの減りは説明できない（ループは出力の 0.1% と 4.1%）。
BGM の上に乗った音声を silero-vad が非音声と判定していると考えるのが妥当で、
**VAD は既知の雑音源に対する道具であって、既定にしてよい前処理ではない。**

## 決定

**日本語の既定モデルを `large-v3-turbo` に変更する。** 根拠:

- 参照のある 3 コーパスで 2 勝 1 分（負けなし）。うち 1 つは対抗モデルの in-domain
- 実音源で 1.45 倍のテキストを出し、ループを除いた条件でもその比が保たれる
- 速度は VAD 併用時 80 秒 対 68 秒でほぼ互角（VAD 無しでは 173 秒 対 86 秒）
- サイズは 547 MB 対 513 MB、ライセンスは MIT 対 Apache-2.0 でどちらも問題ない

`kotoba-whisper-v2.0` はカタログに残す。`--model` で選べる状態を維持し、
既定から外すだけにする。**利用者の設定ファイルに書かれた既定は変更しない** —
明示的に選ばれた値は追随しない（`feedback_config_redirect_vs_persisted_paths` の原則）。

## 同時に入れるもの

**反復ループの警告。** turbo の 48 連続反復は、話者過分割と同じ性質の破綻である —
**出力は完全に整形式で、JSON は妥当で、何のエラーも上がらない。**
`internal/transcript/diagnose.go` が話者数に対してやっていることを、
連続する同一セグメントに対してもやる。既定を、ループを起こしやすいモデルに
変える以上、これは同じコミットで入れるべきものである。

## 積み残し

- 1.45 倍の差が本当に「取りこぼしの回復」なのかは、この音源に参照テキストが
  無い限り確定できない。確定させるなら数分ぶんの人手起こしが要る。
- VAD が落とした 31% の内訳（幻覚 対 実音声）を測っていない。
  ADR-0006 の音源分離（Spleeter）を前段に置いた場合との比較が筋の良い次手。
- ReazonSpeech / CV8 / JSUT はいずれも短い発話の集合で、長時間音声の
  チャンク境界に起因する破綻は測れていない。
