# ADR-0006: 音源分離を前処理に入れない

- Status: Accepted
- Date: 2026-08-09

## Context

ADR-0005 で「固有名詞は復号側では直せない」と結論した後、**前処理で音声だけを抽出すれば
音響側の問題は減るのではないか**という方向が出た。実音源は BGM が全編に鳴り続ける
ドラマ CD で、この BGM は既知の害を出している — 話者分離が 39 分で 93 話者に割れた
（v0.1.3 の警告はこの音源から生まれた）。

「音響の問題は前処理で、文脈の問題はエージェント側で」という分担は筋が通っている。
問題は**それぞれが実際に何を直すか**で、これは測らないと分からない。

## 実装可能性

**第三のランタイムは要らない。** すでに静的リンクしている sherpa-onnx v1.13.4 が
C API を持っている:

| 機能 | モデル |
|------|--------|
| 音源分離（ボーカル / 伴奏） | Spleeter 2stems、UVR MDX-Net |
| ノイズ除去 | GTCRN、DPDFNet |

話者分離と同じ形の CGO ブリッジ 1 本で載る。**技術的な障害は無い。**

## 実測

2026-08-09、M2 Max。Spleeter 2stems（fp16）。同一音源、既定閾値。

**コストは無視できる。** 分離の RTF は **0.038**（文字起こしの 0.186 の 1/5）。

### 効いたもの — 文字起こしの脱落

50 秒の区間で、**原音では繰り返しループに飲まれて丸ごと消えていた一文が復元した**。
原音側は同じ句を 2 度繰り返して次の発話を食い潰しており、分離後はその繰り返しが減って
本来の一文が現れた。

### 効かなかったもの (1) — 固有名詞

問題の姓は分離の前後で**変わらない**（同じ誤りのまま）。ADR-0005 の結論を補強する:
固有名詞は音響側の問題ではない。

### 効かなかったもの (2) — 話者の過剰分割

**これが本命だったが、届かなかった。** 5 分・既定閾値 0.5:

| | セグメント | 話者 | 1 回だけ発話 | 過剰分割の警告 |
|---|---|---|---|---|
| 原音 | 81 | **18** | 8 | 出る |
| ボーカル抽出後 | 66 | **14** | 5 | **出る** |

改善はある（18 → 14）。しかし実際の配役は数人であり、14 は依然として大きく外している。
警告も出たままである。**BGM を除いても過剰分割は残った** — なぜ残るのかは分かって
いない。埋め込みが拾っているものが BGM だけではない、という以上のことは言えない。

したがって、閾値較正（`--speaker-threshold` を上げる、`--speakers` で固定する）が
引き続き主たる対処であり、分離はその代わりにならない。

## Decision

**音源分離もノイズ除去も入れない。**

技術的に可能で、コストも安く、文字起こしの脱落には実際に効く。それでも入れない理由は
**ライセンスである**:

| モデル | コード | **重み** |
|--------|--------|----------|
| Spleeter | MIT | **明示なし。** 「著作物に使うなら権利者の許諾を取れ」との注意書きのみ |
| UVR MDX-Net | MIT（GUI 本体） | **明示なし。** 変換元も第三者の集約リポジトリ |

組織規約では**重みのライセンスは上流の配布元から導出する**（`nlink-jp/knowledge`）。
**「明示なし」はライセンスではない。** 既定カタログに載せられない以上、
`voice-scribe models pull` の一覧に並べることもできない。

ADR-0004 で既定モデルを作者の配布元に戻したばかりでもある。ライセンスの分からない
重みを、その直後にカタログへ足すのは筋が通らない。

opt-in フラグにして利用者に自分でモデルを用意させる形も検討したが、**採らない**。
主たる動機だった話者分離の改善が測って届かなかったため、残る利得は「文字起こしの
脱落が減ること」一点になり、**ステレオ経路の追加**（下記）に見合わない。

## Consequences

- **デコーダは mono/16k のまま**でよい。Spleeter は**ステレオ必須**で（mono を渡すと
  `Invalid channel 1` で落ちる）、入れるなら `internal/audio` にステレオ経路が要った。
  この変更が不要になる
- BGM 付き音源での話者分離は、**閾値較正が引き続き唯一の対処**である。v0.1.3 の
  過剰分割警告がそれを利用者に伝える役目を持ち続ける
- **再検討の条件**: 重みのライセンスが明示された音源分離モデルが sherpa-onnx の
  対応形式（Spleeter / UVR）で現れたとき。その時も、話者分離への効果は改めて測ること
  — 今回の 18 → 14 は「入れる根拠にならない」側の数字だった
- 実測に使った上流 CLI（`sherpa-onnx-offline-source-separation`）は submodule から
  そのまま建てられる。ADR-0005 の `whisper-cli` と同じ手であり、**リンク済みの
  ランタイムが持つ未使用機能を評価する定石**として使える
